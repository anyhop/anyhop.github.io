Run every VPN connection at once.

anyhop keeps several VPN exits live at the same time — one provider or mixed across providers — and sends each connection out the one a rule picks: by domain, by IP range, or everything else by default.

Install

curl -LsSf https://github.com/anyhop/anyhop/releases/latest/download/install.sh | sh

macOS and Linux — installs anyhop and its user-level login service.

  • brew install anyhop/tap/anyhopHomebrew
  • pip install anyhoppip
  • docker pull ghcr.io/anyhop/anyhop:latestDocker

Every method, plus the checksum-verified manual install and the uninstaller, is in Getting started.

The router entrypoint

One entrypoint. Ordered rules. Your exits.

Every connection enters the same local proxy. Rulesets are checked in order and the first match wins, so the order of the blocks is the priority.

Pick one above, or type a destination.

What points here

  • a browser
  • a terminal
  • a container
  • a script
  • the whole machine TUN
  1. 0 BlockTrackers domain tracker.example.com block connection dropped
  2. 1 LocalDirect cidr 192.168.0.0/16 direct no VPN
  3. 2 Streaming domain netflix.com domain hulu.com nordvpn/wg_us_1 127.0.0.1:1081
  4. 3 DefaultVPN all nordvpn/wg_jp_1 127.0.0.1:1082

Rulesets are authored and reordered from the CLI: anyhop routes ruleset create Streaming --via nordvpn/wg_us_1 --domain netflix.com. Traffic that matches nothing goes direct by default, or nowhere with the kill-switch on. See Rule-based routing.

For people

Several locations, at the same time.

Your VPN's own app connects to one location at a time. Switching countries means disconnecting first, and breaking whatever was using the old exit.

anyhop keeps several locations live at once. Point each site or address range at the exit you want, and leave everything else on a default you choose — no switching, no reconnecting.

There is a bundled web UI (anyhop ui) for channels, routes and logs, and a full CLI if you would rather stay in the terminal.

For programs

Every action is also a REST call.

Each channel is a stable 127.0.0.1:<port> proxy, and everything the CLI does is also available over /api/v1 with Bearer auth. Another program can create, probe, rotate and retire VPN connections on its own schedule.

That is what makes proxy rotation across regions — and reaching geofenced resources from wherever they are served — something you can script rather than click through.

The container image is ghcr.io/anyhop/anyhop, so a compose stack can add anyhop as one service and let sibling containers reach the internet through whichever exit the rules pick.
